# GT-Shop

> **全面面向AI的下一代高性能商城系统**
>
> 从商品上架到订单履约、支付退款和经营分析，一套完整的全栈商城系统。

GT-Shop 包含 Go 商城后端、React 运营管理端，以及基于 UniApp 的微信小程序和 H5 用户端。系统重点打磨几个关键问题：**热点请求处理得快、金额算得准、库存扣得稳、异常追得回、运营看得清**。

## 核心亮点

### 01 · 高性能：让热点请求少回源，让数据更新快生效

商品列表和详情的静态信息采用 Redis Cache Aside 缓存，并通过请求合并减少并发访问时的重复数据库查询。商品发生变更后递增缓存世代键，新请求会读取新版本；库存数量则按实时数据查询，避免展示长期滞后的可售库存。

缓存不可用时，请求可以回退到数据库读取。Go 后端集中承载业务 API，订单与售后等高频状态查询配有数据库索引，为持续扩展流量留出清晰的优化路径。

### 02 · AI 用户画像与个性化运营（开发中）

正在开发基于用户浏览、加购和购买行为的 AI 用户画像，让商城更懂每个人的兴趣与消费偏好。目标是把画像用于三类个性化体验：

- **千人千面**：按兴趣展示更相关的商品与内容。
- **喜好优惠券**：根据用户偏好定向推送合适的优惠券。
- **千人千价**：结合用户画像与营销规则，提供差异化价格或权益。

以上属于内测中的能力，当前版本尚未提供完整的用户画像、优惠券推荐和个性化定价流程。

### 03 · 一句话驱动 AI 二次开发

仓库内置覆盖 [Go 后端](.agents/skills/admin-server/SKILL.md)、[React 管理端](.agents/skills/admin-web/SKILL.md) 和 [UniApp 用户端](.agents/skills/miniapp/SKILL.md) 的项目 Skills。它们把模块结构、API 契约、金额精度、权限、交互和验证要求写成 AI 可读取的规则。

二次开发时，开发者用一句自然语言描述需求，支持 Skills 的 AI 编码助手即可按项目规范定位代码、实施修改并完成相关验证；开发者负责确认需求和审核结果，无需逐文件手动改代码。

### 04 · 钱算得准，交易有据可查

商品价格、运费、订单和退款金额以元为单位存入 `DECIMAL`；业务计算使用整数分或十进制处理，避免浮点数参与金额运算。下单时保存商品名称、规格、单价等快照，让后续改价和商品编辑不影响历史订单的含义。

订单、支付、退款和售后各有业务单号；关键请求通过请求 ID 和数据库唯一约束处理重复提交。交易状态与金额记录可以沿着订单一路追到支付和退款。

### 05 · 库存从锁定到归还，始终有账

库存区分实物数量与订单锁定数量，**可售库存 = 实物库存 − 锁定库存**。下单锁库、支付扣减、超时取消还库和售后入库各有明确的变动路径；库存更新使用数据库条件与版本控制，减少并发下的超卖风险。

每次出入库、盘点、锁定、解锁及预警阈值调整都会写入库存流水，保留变动前后数值和操作信息。运营人员可以从商品一路查到 SKU 库存与变动记录。

### 06 · 订单、微信支付、售后连成闭环

订单覆盖待付款、待发货、待收货、完成、取消和退款状态。微信支付 API v3 接入预支付、回调与退款；后台处理超时关单、支付结果核对和退款结果核对，补上回调丢失或外部服务短暂失败后的处理路径。

售后支持仅退款与退货退款：申请、审核、买家寄回、商家收货、发起退款、退款失败与重试都有独立状态和记录。运营端能查看售后详情并处理审核、收货和重试。

### 07 · 后台任务有状态，也能跨实例协调

支付核对、超时关单、自动收货和退款核对由固定任务管理。任务状态记录运行时间、处理数量、失败摘要和下次重试时间；MySQL 租约控制同一任务在多实例中的执行权。失败任务可从管理端查看并按规则重试。

### 08 · API 契约从 Go 一直连到前端

Go DTO、路由和 Swagger 注解定义后台 API，OpenAPI 文档生成 TypeScript 类型与客户端。管理端使用生成的请求和响应类型，接口字段变化能在编译阶段尽早暴露。权限也贯穿菜单、页面、按钮和后端接口，由后端权限校验守住操作边界。

### 09 · 运营台能把复杂业务看清楚

React 管理端覆盖商品、SKU、分类、库存、运费、订单、售后、会员、评价、文件素材、系统设置和经营分析。商品、订单、售后列表提供状态 Tab 与数量统计；商品库存预警遵循 SKU 设置的阈值，已售罄按上架商品的可售 SKU 计算。

界面提供明暗主题、统一列表布局和关键状态提示。数据看板与分析页面把交易、商品、会员和流量数据放到日常运营视角中。

### 10 · 同一套用户端覆盖小程序与 H5

UniApp 用户端包含商品浏览、搜索、购物车、下单、支付、订单查询、地址、评价和售后等流程。Vue 3、TypeScript 与 Pinia 组织跨页面状态，复用业务逻辑服务微信小程序和移动端 H5。

## 技术结构

| 部分 | 实现 | 作用 |
| --- | --- | --- |
| 商城后端 | Go、Gin、GORM、MySQL | 交易、商品、权限、任务与 API |
| 运营管理端 | React、TypeScript、Ant Design、Vite | 商品运营、订单售后处理与经营分析 |
| 用户端 | UniApp、Vue 3、Pinia | 微信小程序与移动端 H5 |
| 支撑能力 | Redis 缓存、Swagger/OpenAPI、微信支付 API v3 | 热点数据、接口契约与支付退款 |

管理端静态资源可以嵌入 Go 服务。业务代码按商品、订单、会员、系统等领域组织，便于沿着一条交易链路阅读和扩展。
