# 05A 微信原生商品分享

## 现状

商品详情已有详情接口、主图、标题、价格及 `onLoad` 的 id 参数处理；未发现 `onShareAppMessage/onShareTimeline`、分享入口和 scene 落地解析。小程序启动配置含通用二维码，但不是商品专属分享链接。

## 执行提示词

先读 README。第一阶段只实现原生商品分享与统一落地，不实现海报、不增加分享奖励或分销参数。

1. 在 `miniapp/src/pages/product/detail.vue` 增加清晰的分享入口；微信端用用户点击的 `<button open-type="share">`，注册页面级 `onShareAppMessage`。数据整备/文案函数可抽离，生命周期仍按 UniApp 页面要求注册。
2. 分享标题来自真实商品名称，path 固定 `/pages/product/detail?id=<合法商品ID>`，imageUrl 使用真实可访问主图。字段缺失时用商城标题/已有占位策略；未加载成功、下架或无效商品不能伪造可购买分享。
3. 支持右上角菜单分享。朋友圈能力按执行时官方文档验证，`onShareTimeline` 返回本页 query 与内容，不照搬好友分享的 path；单页打开时公开商品展示不强迫登录，购买再走既有登录流程。
4. H5 提供“复制商品链接”；使用部署站点实际 origin/base/hash 路由生成，不硬编码开发 localhost 或未知线上域名，不假定普通 H5 可直接调微信小程序分享 API。
5. 抽出 `buildProductShare` / `parseProductEntry` 等小型纯函数，共享给 05B。支持普通 id 和未来扫码 scene：约定短场景 `p=<商品ID>`。id 与 scene 都校验正整数、长度及安全范围；一致或仅一种才接受，冲突/非法内容展示明确错误，不拼接任意路径。
6. scene 按平台语义解码一次，异常编码安全失败；不把启动选项中的数值“启动场景”与小程序码字符串 scene 混淆。来自用户的参数只决定要查询的商品，不能决定价格、权限或账号。
7. 分享文案生成不包含 Token、手机号、订单、会员 ID。不要用分享面板打开/调用完成来提示“分享成功”，不能声称知道对方已经收到。
8. 新入口布局不影响已有 CartDrawer、加入购物车、立即购买；查询商品保持公开 API。应用页面隐藏/回来不重复注册事件或发请求。

## 验收

- 微信好友/群、菜单分享和支持环境下朋友圈，均能落到同一个真实商品。
- 未登录接收人可看详情；商品下架/删除时给出真实状态；主图失败也不崩溃。
- H5 复制链接、刷新直达、不同 base 路径正确。
- id/scene 正常、非法、编码失败、冲突及超长输入都有源码测试；不支持能力按平台降级。
- 按 README 执行小程序检查。分享结果必须真机验证，开发者工具/Mock 只证明本地路由与事件配置。

官方资料：[UniApp 分享与 onShareAppMessage](https://uniapp.dcloud.net.cn/share)。朋友圈与微信特定限制执行时另核对微信官方当前文档。
