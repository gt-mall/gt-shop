# 01 待付款倒计时与超时关单补齐

## 已有代码与缺口

- `admin-server/internal/miniapp/payment/worker.go`：`DefaultOrderExpiry = 30 * time.Minute`，启动立即扫描，随后每分钟扫描。
- `admin-server/main.go` 启动 `RunTimeoutWorker`；`payment/service.go` 的 `CloseExpiredOrders` 分批处理，`closeTimeoutOrder` 在事务内锁订单、释放 locked_stock、关闭待支付记录并记 `timeout_close` 日志。
- `CreatePayment` / `MockPay` 校验订单状态，但没有在付款前直接比较截止时间，因此“已经过 30 分钟、扫描尚未执行”存在继续付款窗口。
- `internal/miniapp/order/types.go` 列表和详情没有服务端当前时间/截止时间；小程序订单页无倒计时。`miniapp/src/utils/date.ts` 已有 `formatCountdown`。
- 已有 `payment_regression_test.go`、`payment_mysql_test.go` 的超时、重试和并发测试，扩充这些用例。

## 执行提示词

先读取本目录 README 公共约束，然后直接完成以下改动。

### 后端

1. 第一版继续沿用“创建时间 + 30 分钟”，不新增可配置订单有效期。把截止计算做成后端单一公共函数/策略，供列表、详情、付款校验和扫描使用，避免多个常量或 miniapp 模块循环依赖。无需为了倒计时新增数据库字段；未来支持动态有效期时再设计持久化快照。
2. 订单列表项、详情及创建响应增加 `payment_expires_at`（带时区 RFC3339 时间；非待付款可为 null）、`server_time`（同一响应使用同一时刻）和 `can_pay`。不得混入缓存的旧 server_time。同步 Go DTO、Swagger 和 `miniapp/src/api/order.ts`。
3. `CreatePayment` 和 `MockPay` 在同一订单行锁保护下，判定 `now >= expires_at` 时不得创建新的有效支付或扣库存。已经成功的支付重试仍返回幂等成功，不能仅因时间已过就改写成功订单。
4. 到期付款请求触发同一关单业务逻辑，正常提交“关单 + 释放锁定库存 + 关闭待支付记录 + 日志”后再返回业务错误。特别注意：不能在 Transaction 回调中完成更新后直接返回“已超时”错误，导致刚才的关单回滚。提取事务内复用函数，不嵌套事务或复制一套关单流程。
5. worker 继续作为无人访问情况下的兜底。支付、主动取消、worker 统一订单优先的锁顺序；只释放锁定库存，不增加可售实物库存，不重复记日志。不增加前端可任意关闭别人订单的接口。
6. 到期边界用可控制时间测试；保持每批失败可继续、后续重试、服务重启扫描的现有能力。定时扫描可能延迟约一个扫描周期，不能承诺数据库状态精确每秒切换。

### 小程序

1. 在 `pages/order/detail.vue` 和 `pages/order/index.vue` 的待付款卡片展示剩余时间，使用 `OrderPaymentCountdown` + 简单 composable 或同等轻量拆分，复用 `formatCountdown`。
2. 根据服务端时间校准时钟，每次 tick 从截止时间重新计算；不能简单每秒减一。列表共用一个计时器，不为每条订单建定时器；隐藏/卸载清理，返回页面刷新与重新校准。
3. 剩余归零立即禁用支付，展示“支付已超时，正在确认订单状态”。向服务器刷新状态，有限退避重查（例如 2/5/10 秒，最多 3 次），仍失败则显示重试入口。只有服务器返回已取消才能展示已取消；不调用用户主动取消接口冒充自动关单。
4. 同步 `OrderActionBar.vue` 的支付可用性；缺少/非法时间时先刷新确认，不能显示 NaN，也不能从本地手机时间断定订单已取消。
5. 到期、刷新、点击付款同时发生时以服务端返回为准，防重复付款请求；保留现有模拟付款提示。

### 验收

- 创建订单返回截止时间；设备时钟快/慢、切后台两分钟再回来，显示仍正确。
- 待付款到期且 worker 未扫到时，调用微信预支付或支付确认均不能成功扣库存，最终订单取消且只解锁一次。
- 支付先完成时，worker 不得取消；worker 先完成时支付失败；成功支付重试维持幂等。
- 关单事务任一步失败全部回滚，下一轮可重试；管理员/另一会员不能借此越权。
- 列表刷新只更新一次到期状态，无一秒一个 HTTP 请求，无计时器泄漏。
- 执行 README 中后端、小程序检查；并发额外运行隔离 MySQL 专项，记录跳过原因。
