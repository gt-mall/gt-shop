# 04 独立搜索页、搜索历史与热门标签

## 已有代码

- 首页 `pages/index/index.vue` 搜索入口目前跳分类页。
- `pages/category/index.vue` 已有关键词、分类、综合/销量/价格排序、分页与部分失败提示。
- `src/api/product.ts` / `internal/miniapp/product/{api,service,types}.go` 已支持 `GET /api/miniapp/products` 的 `keyword/category_id/sort/page/page_size`，搜索商品名称和副标题。
- `utils/storage.ts` 提供本地缓存；后端 `system_config` 与 `internal/system/setting` 提供 JSON 配置和缓存能力。无需引入 Elasticsearch 或新搜索服务。

## 执行提示词

先读 README。第一版是“独立搜索体验 + 本机历史 + 后台配置热门词”，不做联想推荐、语音、拼音、热度分析或全量行为埋点。

### 搜索页

1. 新建 `miniapp/src/pages/search/index.vue`，注册非 Tab 页面；首页与分类搜索入口改为 `navigateTo`。保留分类浏览功能，避免两套长期分叉的搜索交互。
2. 未提交词时展示搜索历史和热门搜索；提交后展示真实商品结果、总数、排序和触底分页，复用 ProductCard。支持路由 `keyword`，可选 `category_id` 必须清晰展示/可取消；首页进入默认全商城。
3. 输入与已提交词分开。仅点搜索、键盘确认、点历史/热门词时发请求；trim、合并无意义空白、长度上限建议 50 字。空词回到发现态，不请求全商城冒充搜索结果。
4. 每次关键词/排序/分类变化重置页码并更新请求序号。旧词返回不能覆盖新词；分页失败页码不推进，重试同一页并按 product_id 去重；有旧结果刷新失败时保留且标明当前生效查询。
5. 正确区分首次加载、无结果、失败、加载更多、无更多；不要用静态演示商品填充空结果。

### 本地历史

1. 提取可测试的 history 工具，使用现有 storage；按规范化关键词去重、最近优先、最多 20 条，可单条删除/确认清空，存储失败不阻断搜索。
2. 默认按会员 ID 隔离，游客独立 key；不使用 Token 作为 key，不混入其他账号历史；退出时清理当前会员历史，游客历史不自动合并。成员身份没准备好时不读取上个账号的数据。
3. 仅明确提交有效关键词时记录；输入过程、空格、重试及翻页不反复记历史。历史不上传后端，不新增数据库表。

### 热门词后台配置

1. 沿 `internal/system/setting` 增加 `search_basic` 配置，字段建议 `hot_keywords: [{keyword, sort, enabled}]`。服务端限制最多 20 条、单词最长 50 字、去重和规范化；空配置合法。
2. 建议新增管理端 `GET /api/system/settings/search`、`POST /api/system/settings/search/save`，沿用查看/更新设置权限并核实读取接口的服务端保护。公开 `GET /api/miniapp/search/config` 只返回启用且排序后的词；这是新增契约，不是假定已有接口。
3. 管理端在系统设置中加入“搜索设置”页/Tab，普通表单支持增删、排序、启停；直接调用生成 Client。名称叫“热门搜索/推荐搜索词”，不伪造实时热度或搜索次数。
4. 复用配置缓存与 generation 失效；保存后小程序刷新可见，Redis 故障仍能读配置。热门词加载失败不阻断用户输入搜索，空配置隐藏该区域。
5. 商品搜索继续走现有 GET products；后端校验 keyword 长度及 sort/page_size，保持上架/未删除过滤、参数化查询和稳定排序（同值追加 id 排序）。如果 `%`/`_` 作为普通用户文字处理，明确转义规则并补测试。

## 验收

- 首页/分类进入、路由预填、搜索/清空、四种排序、结果返回和继续分页。
- 慢请求 A 晚于 B 返回、第二页失败重试、重复商品去重、无结果与失败分离。
- 历史顺序/去重/截断/删除/清空、存储失败、游客/账号 A/B 隔离。
- 热门词保存/启停/排序/空配置、权限拦截、缓存失效；不能用硬编码热门词作为上线成功验收。
- 执行 README 三端相关测试、API 生成和双端构建。
