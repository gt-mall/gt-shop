# 普通 CRUD 页面

## 适用范围

用于新增、修改或精简常规列表 CRUD 页面。当前页面风格以 `admin-web/src/modules/system/user/index.tsx` 为参考；复杂编辑器、图表和特殊交互页面不套用本规范。

普通 CRUD 页面仅调用已有 API 时，直接遵循主 Skill，不读取 `http.md`。只有任务同时涉及 Axios、HTTP、Response、Token、401 或网络异常基础设施时，才按主 Skill 的路由规则读取 `http.md`。

## 页面结构

- 使用 Ant Design 的 `Card + Input.Search + Table + Modal + Form` 组织常规页面，不使用 `ProTable`。
- 删除操作使用 `Popconfirm` 或项目已有确认交互，不额外实现一套确认组件。
- 查询条件和分页放在同一个 state；其余页面状态保持最小化，通常只包含列表数据、总数、加载状态、弹窗状态和当前编辑记录。
- 简单页面保留在模块入口文件中；只有组件确实复杂或被复用时再拆分。

## API 与数据

- 先确认后端 Swagger DTO、注解和路由，再使用生成的 API Client 与类型。
- 禁止手工修改 `generated_api.ts` 等生成文件，也不要为已有生成接口重复编写请求函数。
- 请求参数、分页字段和返回字段以 Swagger Contract 为准，不在页面中猜测后端结构。
- 统一 Response 按 `code`、`message`、`total`、`data` 读取；`code === 1` 才视为业务成功。
- 列表查询成功后更新数据和总数；失败时保留可理解的页面状态并展示统一 `message`。

## 查询与分页

- 查询表单提交时从第一页开始加载。
- 重置查询条件后同步回到第一页并重新加载。
- 页码或每页条数变化后重新请求列表；改变每页条数时优先回到第一页。
- 查询期间设置加载状态，完成后恢复；遵循主 Skill 的异步规范，不使用 Promise 链或异常捕获语法收尾。

## 新增与编辑

- 新增和编辑可以复用同一个表单弹窗，通过当前编辑记录区分模式。
- 打开编辑弹窗时回填记录；打开新增弹窗时清空旧值。
- 编辑优先复用列表行数据，只有列表字段不足时才请求详情。
- 表单校验通过后调用对应生成 API，成功时关闭弹窗、提示结果并刷新列表。
- 失败时保留弹窗与输入内容，展示 Response 中的 `message`。

## 删除

- 删除前必须明确目标记录，并提供确认交互。
- 删除成功后刷新当前列表；当前页最后一条被删除时，避免停留在无数据的越界页。
- 删除失败时展示统一 Response 的 `message`，不伪造成功状态。

## 权限与边界

- 页面涉及权限时，使用 `framework/store` 暴露的权限判断控制入口、按钮和操作；后端鉴权仍是最终安全边界。
- 不在 CRUD 页面自行解析 JWT、复制权限集合或实现 HTTP 拦截器。
- 不为单个页面新增与公共层重复的 Response、Token 或错误处理工具。
