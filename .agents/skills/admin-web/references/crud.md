# CRUD 行为规范

负责常规 CRUD 的 API 调用、查询、分页、新增、编辑、删除和状态管理；不规定页面结构或组件摆放。

> 页面视觉与布局统一以 admin-ui.md 为准，admin-ui.md 优先于历史页面参考。

界面任务同时读取 [admin-ui.md](admin-ui.md)；HTTP 基础设施与权限规则按主 Skill 路由读取，不在页面另建实现。

## API 与状态管理

- 使用生成 API 与类型，请求参数、分页字段和返回字段以 Swagger Contract 为准，不猜测接口结构。
- 统一 Response 读取 `code`、`message`、`total`、`data`；`code === 1` 才视为业务成功，失败展示返回的 `message`，不伪造成功状态。
- 已生效查询条件和分页统一管理；提交查询的页面可另存未提交的筛选输入。其余状态只保留列表、总数、加载、弹窗和当前编辑记录等实际需要的数据。
- 请求期间维护对应加载状态，成功或业务失败后均恢复；异步语法遵循主 Skill。
- 列表成功后更新数据和总数；失败与空数据明确区分，保留可理解、可重试的页面状态。

## 查询与分页

- 提交或重置查询条件时回到第一页并重新加载。
- 页码变化后重新请求；改变每页条数时回到第一页。
- 默认每页 20 条，提供 10 / 20 / 50 / 100 条选项；实际参数遵循接口支持范围。

## 新增与编辑

- 简单新增和编辑可共用表单弹窗，通过当前编辑记录区分模式。
- 打开编辑时回填记录，打开新增时清空旧值；列表字段足够时直接复用，不足时请求详情。
- 表单校验通过后调用生成 API；成功时关闭弹窗、提示结果并刷新列表，失败时保留弹窗与输入内容。

## 删除

- 删除前明确目标记录，使用 `Popconfirm` 或项目已有确认交互，不另造确认组件。
- 删除成功后刷新列表；删除当前页最后一条时回退到有效页，避免停在无数据的越界页。
